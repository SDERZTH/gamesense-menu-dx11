# gamesense-menu

A standalone **Direct3D 11 + Dear ImGui** recreation of the gamesense menu. The original menu appearance, layout, GDI glyphs, icons, control behavior and visibility rules are preserved.

This is a menu preview. Settings change the local UI state; game features and Lua execution are not implemented.

## Build

Needs Visual Studio with the **Desktop development with C++** workload and Windows SDK. Run `build.bat` to build the x64 Windows application:

```
.\build.bat
.\gsmenu.exe
```

Outputs: `gsmenu.exe` and `build/gsmenu-dx11.exe`. Close the running preview before rebuilding, or use `build.bat --no-copy` to update only the build-directory EXE. The C++ runtime is statically linked. All images are embedded; there are no runtime downloads, additional asset folders, or ImGui INI files.

Dear ImGui **v1.92.9b** and its unmodified Win32/DX11 backends are vendored in `third_party/imgui/`. `SOURCE.json` records the upstream commit and SHA-256 of each file; the MIT license is included.

## Layout

- `main.cpp`: original GDI font atlas, embedded PNG decoding, menu setup and DPI handling
- `renderer_dx11.h`: DX11 device/swap chain, GPU textures, ImGui drawing primitives and BMP capture
- `app_dx11.h`: native window, ImGui frame lifecycle and queued input dispatch, resource cleanup
- `ui.h`: custom widgets with the original drawing, layout, input semantics and groupbox clipping
- `menu_data.h`: the full menu tree, **generated** by `re/gen.js`
- `menu_rules.h`: visibility and enable rules, per-weapon configs, weapon Copy/Paste
- `assets_data.h`: embedded PNGs, generated by `re/embed.js` from `assets/`
- `re/`: the data pipeline and its outputs (see `re/README.txt`)
- `ref/`, `diff.js`: pixel regression check against a reference capture of the Misc tab
- `legacy/dx9/`: preserved original source and build script for direct visual comparisons
- `tools/check_parity.py`: dependency-free DX9/DX11 render comparisons

Dear ImGui owns draw lists, GPU draw submission, clipping and the Win32 input queue. The controls retain their custom drawing and original event logic to keep their appearance exact, rather than adopting the stock ImGui widget style. The same quad triangulation as the DX9 source also preserves gradient and fade rounding.

## Testing hooks

```
gsmenu.exe --capture out.bmp
gsmenu.exe --capture out.bmp --tab rage --dpi 150 --state state.json
gsmenu.exe --capture software.bmp --warp
node diff.js out.bmp ref/misc.bgra
```

- `GS_EVENTS="down:x,y;move:x,y;up:x,y;rdown:x,y;rup:x,y;key:vk;wheel:x,y,d,ctrl"` replays input before the capture.
- `GS_RESIZE=WxH` resizes the window.
- `--tab`: `rage`, `aa`, `legit`, `visuals`, `misc`, `skins`, `players`, `config` (or indices 0–7).
- `--dpi`: `100`, `125`, `150`, `175`, `200`.
- `--state`: writes renderer/version, tab, scale, vertex count and element state as JSON.
- `--warp`: requests the Direct3D software fallback. It is also used automatically if hardware device creation fails.

`GS_EVENTS` is the original deterministic control-state replay hook. Normal interactive input passes through the Dear ImGui Win32 backend and event queue.

To compare against the original source on the same machine:

```
.\legacy\dx9\build.bat
.\build.bat
python tools\check_parity.py
```

The check compares 27 scenes, including all eight tabs, all five DPI scales, dropdowns, sliders, clipboard context menus, hotkey binding, color pickers, scrolling and a larger client area. Hardware captures must match every RGB pixel. The software fallback is checked separately with a one-level channel tolerance because its rasterizer rounds differently. Results and captures go to `build/parity/`.

The original `ref/misc.png` is an older reference with slightly different visible settings. Port fidelity is measured against the rebuilt, unchanged source in `legacy/dx9/`, using the same system fonts and graphics adapter. Native mouse/keyboard and window resizing are checked separately in the running preview.
